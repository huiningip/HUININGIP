## Why these skills are different

They are written the way a practitioner files, not the way a chatbot explains:

- **Volatile data carries a freshness stamp.** Fees, individual fees, contracting-party declarations, membership counts and legal texts each come with an as-of date, a review interval and an official verification entry point.
- **No invented facts.** When something cannot be found, the skill answers "none". It does not estimate, guess, or fill the gap with a placeholder.
- **Citations you can verify.** The Agreement, Protocol, Regulations and Administrative Instructions are bundled as verbatim texts, paired across Chinese and English, so every conclusion traces back to the source paragraph.
- **Computable things are scripts.** Deadlines, fee schedules and renewal windows are reproducible code with self-tests — not prose.
- **One structure throughout.** Role → Task → Context → Process → Rules — the same skeleton across the whole family.

## 这些技能的不同之处

按代理人办案的方式写，而不是按聊天机器人的方式讲：

- **易变数据带时效戳** —— 规费、单独规费、缔约方声明、成员数、法律文本均标注基准日、建议复核周期与官方核验入口。
- **零编造** —— 查不到直接回「无」，不估算、不猜测、不用占位符填充。
- **引用可核** —— 协定、议定书、实施细则、行政规程以逐字全文内置，中英成对，每条结论都能回溯到原文段落。
- **能算的都写成脚本** —— 期限、费用、续展窗口是可复现的代码（带自检），不是散文。
- **统一结构** —— 角色 → 任务 → 上下文 → 流程 → 规则，全族同一骨架。
